3. **비상시**: `⏸ 일시정지` / `▶ 재개` (모든 화면이 같은 지점에서 멈추고 이어짐), 문제가 크면 `⛔ 비상 중단`

## 설계 (안정성)

### 서버가 정하고, 모든 기기가 같은 장면을 그린다
- **서버가 정하는 것**: 시드(난수) · 출전 명단(시작 순간 고정) · 경주 시간 · 출발 시각 · 일시정지 누적. 어떤 브라우저도 바꿀 수 없음
- **각 기기**: 서버 값으로 결정론적 엔진(정수 연산만)을 돌려 전체 경주를 수 ms 에 미리 계산 → `서버 시각 − 출발 시각 − 정지 시간` 으로 현재 장면을 그림. 경주 중 네트워크로 오가는 건 3초마다의 작은 상태 조회뿐
- **공식 결과**: 관리자 화면이 계산해 제출 → 서버가 검증(경주 시간 경과, 엔진 버전, 명단·등수 정확성) 후 저장. 휴대폰들은 자기 계산 해시를 보고 → 관리자 화면에 일치 수 표시. 불일치 시 서버 공식 결과를 표시
- 한계: 서버(DB)가 경주를 직접 계산하지는 않음. 필요하면 Supabase Edge Function 으로 같은 엔진을 서버에서 실행해 교차 검증 가능 (별도 배포 필요)

### 시계 동기화
서버 시각을 5번 물어 왕복이 가장 빠른 표본들로 기기 시계 차이를 추정(NTP 방식). 기기 시계가 몇 분 틀려도 무관. 30초마다·화면 복귀·네트워크 복구 시 재동기화, 작은 보정은 천천히 반영해 화면이 튀지 않음.

### 참가 · 연결
- Supabase Auth 미사용 (익명 로그인은 IP당 제한 → 행사장 Wi-Fi 하나로 50명이면 막힘). 기기 비밀 토큰의 해시만 저장
- 모든 쓰기는 서버 함수로만, 서버가 검증. 참가/조회는 멱등 → 타임아웃·연타·재시도 안전
- 관리자 "동작"(시작·정지 등)은 자동 재시도 안 함 (응답 유실 시 두 번 실행 방지) — 실패하면 화면이 상태를 다시 읽음
- 실시간 + 폴링 안전망. 휴대폰은 드물게 바뀌는 게임 상태만 실시간 구독 (Realtime 메시지 한도 보호)
- 엔진 버전이 다른 옛 화면이 캐시돼 있으면 경주당 1회 자동 새로고침
- 참가 후 화면 꺼짐 방지 (Wake Lock, 지원 브라우저)

### 관리자 인증
비밀번호(솔트 + SHA-256 5000회) → 12시간 세션 토큰 (탭 단위 저장). 5회 실패 시 60초 잠금. 비밀번호 변경 시 다른 세션 모두 종료.

### 경주 엔진
정수 연산만 사용하는 결정론적 시뮬레이션 (iOS/Android/PC 비트 단위 동일). 경주 시간 30~180초를 시간 축 전체 비례로 조정해 어떤 설정이든 이벤트 약 26건·역전 5~7%. 개그 이벤트도 같은 난수로 시뮬레이션 안에서 발생 → 조작 불가.

⚠️ `src/engine/` 수정 시 결과가 바뀝니다 → `ENGINE_VERSION` 올리고 `npx vitest run -u` 로 GOLDEN 갱신. **11/20 이후 엔진 수정 금지.**
